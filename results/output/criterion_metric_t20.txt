Read the oracle-to-random gap FIRST, per region. If greedy_oracle and the random band
overlap, the metric does not discriminate there and nothing below it is readable.

`greedy_oracle` is a reference, not a bound: greedy declines a low-gain split that
unlocks large gains two levels down, so a criterion beating it at some budget indicates
LOOKAHEAD VALUE and is not a bug. There is no assertion anywhere that it dominates.

`nan%` is how much of the region a signal declines to score. A signal that is NaN
nearly everywhere is not ranking; NaN never wins a comparison, so its curve is the
tie-break's scan order. Read `escaped:` above for why escape_grad is that at t=13.

Read `distinct`/`modal%` before the curves. A criterion whose signal takes ONE value
across the region is not ranking at all -- its curve is the tie-break's scan order, and
a flat curve there means `no ordering`, not `a bad ordering`. Those are different
faults with different fixes and the error curve alone cannot separate them.

error(full) is exactly 0 by construction -- the reference IS the fully-refined tree.
That makes the zero locatable, not meaningful as image quality: at the screen floor
sub-pixel structure is sampled arbitrarily, so `error = 0` reads as `matches this
sampling`.
