Cost-aware priority is worth building only if the cost distribution is WIDE. Read
p99/p50, not the mean: a long tail with a tight bulk buys nothing for the typical quad,
which is what a scheduler decides about. If greedy_oracle and greedy_oracle/cost give
the same curve, cost-weighting has nothing to move.

Anisotropy: a high `all four keep` fraction means an isotropic split is mostly wasted
and a 2-way split along the disagreement direction -- which §3.2's layout already
measures -- would be strictly cheaper. This is a COSTING. Nothing anisotropic is
implemented, and the tau sweep is there because a single tau would make the case look
settled when it is a function of a knob that moves trees 64x.
